## Hard rules (violating any of these is a stop, not a style choice)

1. **No new crates.** `serde_json` and `ureq` only, exactly as `Cargo.toml`
   has today. No async runtime, no HTTP server crate, no TLS crate.
2. **The worker core is untouched.** `file`, `exec`, `screen`, `cu-abi`, the
   turn loop and every core bound stay byte-identical in behaviour. The only
   permitted core edit is the additive, proxy-capable transport constructor
   in `src/wire.rs` (plan section 5), with its own tests.
3. **No `[no]` is lifted.** The canonical list is `PRD.md` "Non-goals". If a
   task seems to need budgets, rate limits, a key store, a management verb, a
   UI, a second listener, workflow execution or a provider metadata table,
   you have misread the task -- stop and report.
4. **`PRD_01_27` is read-only for you.** Contract contradictions are reported,
   never fixed in place by the implementer.
5. **Secrets are radioactive.** No credential byte ever reaches a log line,
   an evidence row, a mirror line, an inspect response, a header or an error
   string. `Debug` for secret-holding structs must redact. M6 is a CI scanner,
   not a review opinion.
6. **Every local refusal is a named constant** from plan section 6, and every
   upstream status/body passes through verbatim with the `x-gate-*` headers
   added. Never rewrite an upstream error into a different status.
7. **Bounds hold in every build.** No test-only relaxation of a numeric bound.
8. **Files are LF.** The repo has been bitten by CRLF in CI before.
9. **Record, don't rewrite.** When a W completes, append a W-record section to
   `plan/v0.0.20.md` (what shipped, test counts, CI run ids, deviations).
   Do not rewrite PRD.md, `PRD_01_23`/`_24`/`_27` or `prd_hist.md`; report
   what should change there instead.
10. **Commits** follow the repo style: `feat:` / `fix:` / `test:` / `docs:`
    with a one-line reason, like the log you see in `git log --oneline`.

## Entry criteria that are yours to measure

- **Before W3 code: run the G1 spike** (plan 12). Can `ureq`'s custom
  `Transport` carry an already-connected `TcpStream` so the gate owns the
  `CONNECT` handshake? Write the spike as a test, record the verdict in the
  plan, then build W3 on the answer. The fallback is already decided (a
  minimal request/response path over the tunnel, `openai-chat` only) -- use
  it if the seam fails, and say so in the W3 record.
- **In W2: prove G4** -- the slash model id `gate/planner` works through the
  repo's own client: `minicon-harness --base-url http://127.0.0.1:8787/v1
  --model gate/planner --key-env GATE_TOKEN` against a stub upstream.
- **In W4: measure G2** (SSE against the core client and one raw client) and
  **G7** (sidecar sizes; per-OS binaries are the default).

## Stop and report when

- the contract and the plan disagree, or the contract is silent on something
  you must decide (naming, an error shape, an ordering);
- a bound in `PRD_01_27` cannot be met without a new crate or a core change;
- the G1 spike fails both paths;
- a real client does something the contract forbids tolerating (e.g. rejects
  the slash model id outright);
- you are about to edit a file listed as read-only in rule 4 or 9.

Report format: what you built, which M-rows are green with which tier, the
CI run ids, deviations from the plan, and open questions with your proposed
answer. The controller (this session's owner) will upsert the plan.
